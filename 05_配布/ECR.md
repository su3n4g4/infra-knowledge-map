# ECR（Elastic Container Registry）

AWS が提供するコンテナレジストリ。CI がビルドしたイメージを置き、ECS がタスクを起動するときにここから取得する。

仕組みと設計の考え方は [[コンテナレジストリ]] にまとめています。この解説では、**ECR に固有の部品・初期値・動き** だけを扱います。

## なぜ必要か

コンテナレジストリを自分で運用すると、その保存先のディスクや、レジストリ自体のサーバーの管理が要ります。ECR を使うと、それを AWS に任せられます。

- 権限を IAM で管理でき、ECS のタスクには追加の設定なしで取得の権限を渡せる
- 保存できる量を気にしなくてよい
- 脆弱性のスキャンを設定だけで有効にできる

## 概念との対応

| コンテナレジストリの概念 | ECR での名前 |
|---|---|
| イメージを入れる箱 | リポジトリ |
| 同じタグへの上書きを禁止する | タグのイミュータビリティ |
| 古いイメージを消す決まり | ライフサイクルポリシー |
| 誰が push・pull できるか | IAM のポリシー、リポジトリのポリシー |
| 中身の脆弱性の確認 | イメージのスキャン |

## 前後のつながり

- [[AWS構成]]（AWS 全体）：[[CI]] → **ECR** → [[ECS]]

## 初期値と変える値

| 設定 | 初期値 | 何に効くか | 変える目安 |
|---|---|---|---|
| タグのイミュータビリティ | 無効（上書きできる） | 同じタグに別のイメージを置けるか | 有効にする |
| ライフサイクルポリシー | なし（すべて残る） | 古いイメージを消す決まり | 保存の費用が気になるなら設定する。戻す可能性のある数世代は残す |
| push 時のスキャン | 無効 | push のたびに脆弱性を確かめるか | 有効にする |

## 実装に固有の動き

### ログインのトークンに期限がある
CI などから push するときは、AWS の認証情報で ECR のログイン用のトークンを取得してから `docker login` します。このトークンは 12 時間で切れます。

```bash
aws ecr get-login-password --region ap-northeast-1 \
  | docker login --username AWS --password-stdin <アカウントID>.dkr.ecr.ap-northeast-1.amazonaws.com
```

### ECS のタスクは「実行ロール」で取得する
ECS がイメージを取得するときは、タスクの **実行ロール** の権限を使います。アプリ自身が使うタスクロールではありません → [[ECS]]

### プライベートサブネットからは経路が要る
プライベートサブネットのタスクが ECR からイメージを取得するには、外へ出る経路が要ります。NAT Gateway を通すか、VPC エンドポイントを作ります。VPC エンドポイントで済ませる場合は、ECR 用（`ecr.api` と `ecr.dkr`）に加えて、イメージの中身が保存されている S3 用のエンドポイントも必要です。

## 障害

| 症状 | 原因 | 確かめ方 |
|---|---|---|
| タスクが `CannotPullContainerError` で起動しない | 実行ロールに ECR の権限が無い、タグが存在しない、経路が無い | エラーの詳細の文言で分かれる。権限なら実行ロール、経路ならサブネットのルートと VPC エンドポイントを見る |
| CI から push できなくなった | ログインのトークンの期限切れ、CI の IAM の権限不足 | CI の中で、push の直前にトークンを取り直しているか見る |
