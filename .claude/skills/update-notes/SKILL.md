# ノートを更新する

渡された知識を、このリポジトリの解説とマップに取り込む。決まりの正本は `README.md`。迷ったら README に従い、README に無いことは決めずにユーザーに聞く。

## 0. 読む

1. `README.md` を読む（種類、見出し、粒度、前後のつながり、属性、小分類の決まり）
2. `_maps/00_全体マップ.md` を読み、どんな解説があるかをつかむ

## 1. 置き場所を決める

渡された知識を1文にまとめ、次のどれかに決める。

| 場合 | すること |
|---|---|
| 既存の解説の範囲に入る | その解説に追記する。見出しは README の「粒度のルール」の1項目＝1つに合わせる |
| 既存の概念を、特定の環境で実現するもの | 新しい「実装」の解説。概念の解説が無ければ、先に概念を作るかユーザーに聞く |
| どの解説にも入らない | 新しい解説。種類（概念・実装・問題・判断・考え方）を README の表で決める |

新しい解説を作る、小分類を増やす、マップを増やす、のどれかになるときは、書き始める前に、決めた内容（ファイル名、種類、分類、小分類、載せるマップ）をユーザーに見せて確かめる。追記だけのときは確かめずに進めてよい。

## 2. 事実を確かめる

- 設定の初期値、上限、サービスの仕様は、公式ドキュメントで確かめる。確かめられなかったことは書かず、ユーザーに伝える
- 渡された知識と公式ドキュメントが食い違うときは、書く前にユーザーに伝える
- 書いた解説の属性 `確認日` を、確かめた日（`YYYY-MM-DD`）にする

## 3. 解説を書く

- 新しい解説は `_templates/解説_<種類>.md` をもとにし、分類のフォルダに置く。ファイル名は技術の名前だけ
- 冒頭の定義は、たとえを使わず、プロセス・ポート・IP など実際に動くものの言葉で書く
- 小分類は README の「小分類」の表から選ぶ。合うものが無ければ、表に足してよいかユーザーに聞く
- 「関連する解説」に書いた相手の解説の「関連する解説」にも、こちらへの1行を足す

## 4. マップに載せる

載せるマップを、README のマップの一覧と決まりで選ぶ（言語やフレームワークに固有のものは載せない。AWS の配置には実装の解説を、共通のマップには概念の解説を載せる）。

マップ1枚ごとに、次の3つを必ず一緒に更新する。

1. 説明ページ（`_maps/<マップ>.md`）の表に1行足す。最後の列に `[[解説]]`
2. 同じページの Mermaid に、部品と矢印を足す
3. 図（`_maps/<マップ>.canvas` か `_maps/<マップ>.excalidraw.md`。そのマップにある方）に箱を足す

図の箱は、今の図に合わせる。

### キャンバス（.canvas）のとき

| 箱 | 書き方 | 大きさ | 色 |
|---|---|---|---|
| 解説を指す箱 | `### [[解説]]\n1文の説明` | 260×130（長い説明は 300×130） | なし |
| 利用者・外部 | `## ブラウザ` など | 220×100 | `"5"` |
| 通信の制限・症状 | `**SG：〜を許可**` など | 内容に合わせる | `"1"` |
| 注意書き | `**〜** → [[解説]]` | 内容に合わせる | `"4"` |

- 箱は同じ枠（group）の中で、縦に 170 ずつずらして並べる（y が 40、210、380 …）。今ある箱と重ならないことを、座標で確かめる
- id は、ほかと重ならない短い英字にする
- 流れのマップでは、矢印（edges）に `label` で順番や通信の内容を書く
- まだ解説が無い部品も、`[[名前]]` で書いてよい。そのときは全体マップの「これから書く解説」の表に名前を足す

### Excalidraw（.excalidraw.md）のとき

ファイルは、上に `## Text Elements`（文字の要素ごとに `本文 ^id`）、下の `%%` の間に `## Drawing` の JSON がある形。箱を1つ足すには、次の3か所をそろえて書く。

1. JSON の `elements` に四角（`rectangle`）を足し、`boundElements` に文字の id を入れる
2. JSON の `elements` に文字（`text`）を足す。`containerId` に四角の id、`frameId` に枠の id。`rawText` は `[[解説]]` を含む元の文、`text` と `originalText` は `[[ ]]` を外した表示用の文
3. `## Text Elements` に、`rawText` と同じ文を ` ^<文字の id>` 付きで足す（点検はここのリンクを読む）

| 箱 | 書き方 | 大きさ | 色（backgroundColor） |
|---|---|---|---|
| 解説を指す箱 | `[[解説]]\n1文の説明` | 260×130 | `transparent` |
| 項目の箱（枠の中に並べる） | `名前：1文の説明` | 432×60（3行になるなら 80） | `transparent`（目立たせる1つだけ `#a5d8ff`） |
| 利用者・外部 | `ブラウザ\nlocalhost:8080` など | 220×100 | `#99e9f2` |
| 通信の制限・症状 | 見出しの1行と、`・` の箇条 | 内容に合わせる | `#ffc9c9` |
| 注意書き | 文の中に `[[解説]]` | 内容に合わせる | `#b2f2bb` |

- id は 8 文字にする（Obsidian の Excalidraw プラグインが `^id` を 8 文字として読む）。ほかと重ならないこと
- 字は `fontFamily: 2`、本文 16。箱からはみ出さないよう、`text` に改行を入れて折り返す（全角1文字＝字の大きさ、半角＝その半分強）
- 枠（`frame`）は入れ子にできない。枠の中の区切りは破線の四角にする。箱が枠からはみ出していないことを座標で確かめる
- 矢印は `startBinding` / `endBinding` で箱につなぎ、両端の箱の `boundElements` にも矢印の id を入れる。ラベルは `containerId` が矢印の文字
- 手で描き足すなら、Obsidian で図を開いて直接編集してもよい。保存すると、プラグインが同じ形で書き直す

## 5. 解説から戻る道を書く

載せたマップごとに、解説の「前後のつながり」に1行足す。形は README の「前後のつながり」の表に従う。

```markdown
- [[1リクエストの流れ]]（④）：[[DNS]] → [[CDN]] → **ロードバランサー** → [[Nginx]]
```

マップに載せなかった解説は、`マップには直接載らない（〜として載る）：…` の1行にする。

## 6. 全体マップを更新する

新しい解説を作ったときは、`_maps/00_全体マップ.md` の「分類 → フォルダ」の表の、その分類の行に `[[解説]]` を足す。

## 7. 点検する

```txt
node scripts/check.js
```

エラーが0件になるまで直す。点検で見つからないことは、自分で確かめる。

- 図の箱が、ほかの箱や枠の外にはみ出していないか
- Mermaid の構文が壊れていないか（括弧、引用符、`<br/>`）

## 8. 伝える

ユーザーに次を短く伝える。コミットやプッシュは、頼まれたときだけ行う。

- 追記・作成した解説と、載せたマップ
- 公式ドキュメントで確かめられなかったこと、食い違っていたこと
- 点検の結果
