# N+1 問題

一覧を1回のクエリで取得したあと、その1件ごとに追加のクエリを発行してしまう書き方。100件を表示すると、クエリが 101 回発行される。

## なぜ問題か

1回のクエリには、SQL を送って結果を受け取る往復の時間がかかります。1回が数ミリ秒でも、100 回、1000 回と繰り返せば、それだけで画面の表示が遅くなります。DB にとっても、同じような小さなクエリが大量に届くことになり、CPU を消費します。

しかも、**件数が少ない開発環境では気づきにくく、本番のデータ量で初めて遅くなる** ので、見つけにくい問題です。

## 起きる仕組み

### 例（Laravel）

```php
$books = Book::all();               // ① 本の一覧を取る：1回
foreach ($books as $book) {
    echo $book->author->name;       // ② 本ごとに著者を取る：N回
}
```

```sql
SELECT * FROM books;                    -- 1回
SELECT * FROM authors WHERE id = 1;     -- 本の数だけ繰り返す
SELECT * FROM authors WHERE id = 2;
SELECT * FROM authors WHERE id = 3;
...
```

`$book->author` に触れた瞬間に、裏でクエリが走ります（遅延読み込み）。コードの見た目ではクエリが1つしか無いように見えるのが厄介な点です。

ORM を使わない場合でも、ループの中で `db.Query` を呼ぶ書き方（Go など）で同じことが起きます。

## 前後のつながり

- [[1リクエストの流れ]]（⑤）：アプリのコード → [[接続プール]] → [[データベースサーバー]]（**大量の小さなクエリが届く**）
- [[障害の切り分け]]：「全体が遅い」ときに、クエリの回数で疑う

## 見つけ方

| 症状 | 確かめ方 |
|---|---|
| 一覧の画面だけ遅い。件数が増えるほど遅くなる | 1回の表示で走るクエリの数を数える（Laravel Debugbar など） |
| DB の CPU が高い | クエリの統計に、形が同じで ID だけ違うクエリが大量に並んでいないか見る |
| スロークエリログには何も出ないのに遅い | 1つ1つのクエリは速いので、スロークエリログには出にくい。**時間ではなく回数** を見る |

## 直し方

### 1. ORM でまとめて取る
- どうするか：関連するデータを、最初のクエリと一緒に取るよう指定する（Laravel の `with`、GORM の `Preload`）

```php
$books = Book::with('author')->get();
```

```sql
SELECT * FROM books;
SELECT * FROM authors WHERE id IN (1, 2, 3, ...);   -- 1回で全員分
```

- 使う場面：ORM を使っているとき。100件でも 2 回のクエリで済む

### 2. JOIN で1回にする
- どうするか：`SELECT ... FROM books JOIN authors ON ...` のように、1つのクエリにまとめる
- 使う場面：SQL を自分で書いているとき。取りたい列が決まっているとき

### 3. ID を集めて IN 句でまとめて取る
- どうするか：一覧から ID を集め、`WHERE id IN (...)` で1回で取ってから、コードの中で組み合わせる
- 使う場面：JOIN にすると行が増えすぎるとき。別の DB やサービスから取るとき

### 4. 起きた時点で気づけるようにする
- どうするか：Laravel なら開発環境で `Model::preventLazyLoading()` を有効にし、遅延読み込みが起きたらエラーにする。レビューで「ループの中でクエリを投げていないか」を見る
- 使う場面：新しく書くコードで、N+1 を作らないようにしたいとき
