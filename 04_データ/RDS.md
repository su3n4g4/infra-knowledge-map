# RDS（Relational Database Service）

AWS が提供するデータベースサーバーのサービス。MySQL や PostgreSQL などの DB を、AWS がバックアップ・更新・障害時の切り替えまで含めて運用する。

仕組みと設計の考え方は [[データベースサーバー]] にまとめています。この解説では、**RDS に固有の部品・初期値・動き** だけを扱います。

## なぜ必要か

DB のサーバーを自分で運用すると、次の作業をすべて自分で持つことになります。

- バックアップと、その保管・世代の管理
- OS と DB のセキュリティ更新
- 複製の設定と、プライマリが止まったときの切り替え
- ディスクの増設

RDS を使うと、これらを設定で選ぶだけで済みます。その代わり、OS にはログインできず、DB の設定も RDS が用意した方法でしか変えられません。

## 概念との対応

| データベースサーバーの概念 | RDS での名前 |
|---|---|
| DB のサーバー | DB インスタンス |
| 接続先 | エンドポイント（名前） |
| 同期の複製と自動の切り替え | マルチ AZ 配置（スタンバイ） |
| 読み取り用の複製 | リードレプリカ |
| DB の設定ファイル（MySQL の `my.cnf`） | パラメータグループ |
| 全体の写し ＋ 変更の記録 | 自動バックアップ（保持期間内の任意の時点に戻せる） |
| 手動で取る全体の写し | スナップショット |
| 誰が接続できるか | セキュリティグループ、サブネットグループ |

```txt
[アプリ] ──▶ エンドポイント（名前）
                │
                ▼
     [プライマリ（AZ-a）] ──同期で複製──▶ [スタンバイ（AZ-c）]
                │                          ※ スタンバイには接続できない
                └──非同期で複製──▶ [リードレプリカ]（読み取り専用。別の名前で接続）
```

## 初期値と変える値

| 設定 | 初期値 | 何に効くか | 変える目安 |
|---|---|---|---|
| マルチ AZ | 作成時に選ぶ | プライマリが止まったときの自動の切り替え | 本番では有効にする |
| `max_connections` | インスタンスのメモリから自動で計算 | 同時に受け付ける接続の上限 | アプリ側の接続数の合計が超えるなら、先にアプリ側を絞る。それでも足りなければインスタンスを大きくする |
| `slow_query_log` | 無効（0） | スロークエリログ | 有効にする。`long_query_time`（初期値 10 秒）も 1 秒程度に下げる |
| `log_output` | TABLE | ログの書き出し先 | コンソールや CloudWatch Logs で見るなら FILE にする |
| 自動バックアップの保持期間 | 作成方法による（最大 35 日） | 何日前まで戻せるか | 戻したい日数に合わせる |
| 削除保護 | 作成時に選ぶ | 誤ってインスタンスを削除するのを防ぐ | 本番では有効にする |
| 自動マイナーバージョンアップグレード | 有効 | メンテナンスの時間帯に、DB の小さな更新を自動で当てる | 当てる時間帯（メンテナンスウィンドウ）を、アクセスの少ない時間に設定する |

## 実装に固有の動き

### 切り替えは「名前の指す先」が変わる
マルチ AZ で切り替えが起きると、エンドポイントの名前が指す IP アドレスが、スタンバイの方に変わります。切り替えには通常 1〜2 分かかり、その間の接続は失敗します。アプリは IP ではなく名前で接続し、切れた接続を作り直せるようにしておきます → [[DNS]]、[[接続プール]]

### 初期のパラメータグループは変更できない
最初に付いている初期のパラメータグループは、値を変えられません。設定を変えるには、自分でパラメータグループを作り、インスタンスに付け替えます。値によっては、反映に再起動が必要です。

### 戻すと、別のインスタンスができる
自動バックアップやスナップショットから戻すと、元のインスタンスが書き換わるのではなく、**新しいインスタンスが別のエンドポイントで作られます**。アプリの接続先を切り替える手順まで含めて、戻す手順を用意しておきます。

### メンテナンスで再起動することがある
更新を当てるとき、メンテナンスウィンドウの時間帯に再起動が入ることがあります。マルチ AZ なら、スタンバイ側で先に当ててから切り替えるので、止まる時間を短くできます。

### 接続を束ねる RDS Proxy
アプリと RDS の間に RDS Proxy を置くと、多数のアプリの接続を少数の DB の接続に束ねられます。台数が多く `max_connections` に当たりやすい場合や、切り替えの時間を短くしたい場合に使います。

## 障害

RDS に固有のものだけを挙げます。DB 全般の障害は [[データベースサーバー]] を参照してください。

| 症状 | 原因 | 確かめ方 |
|---|---|---|
| 1〜2 分だけ全く接続できない | マルチ AZ の切り替え、メンテナンスでの再起動 | RDS の「イベント」に、切り替えや再起動の記録が残る |
| パラメータを変えたのに反映されない | 初期のパラメータグループを使っている、または再起動が必要な値 | インスタンスに付いているパラメータグループと、その値の「保留中の再起動」を見る |
| バックアップから戻したのに、アプリのデータが古いまま | 戻すと新しいインスタンスができるが、アプリは元のエンドポイントに接続したまま | アプリの接続先の設定を見る |
| アプリから接続できない | セキュリティグループでアプリからの 3306 番を許可していない、別の VPC にある | セキュリティグループの許可元が、アプリのセキュリティグループになっているか見る |
