# DNS

ドメイン名（`example.com`）を IP アドレス（`203.0.113.10`）に変換する仕組み。ブラウザやアプリは、通信を始める前に DNS サーバーへ問い合わせて、接続先の IP アドレスを受け取る。

## なぜ必要か

コンピュータ同士の通信は、IP アドレスを宛先にして行います。でも人は数字の並びを覚えられませんし、サーバーを入れ替えると IP アドレスが変わることもあります。

そこで、**名前と IP アドレスの対応表** を別に持ち、通信の前に「この名前の IP アドレスは？」と問い合わせる仕組みが DNS です。名前さえ変えなければ、裏の IP アドレスを切り替えても利用者は気づきません。

## 仕組み

### 名前解決の流れ

ブラウザで `example.com` を開くと、通信の前に次の問い合わせが走ります。

```txt
ブラウザ
  │ ① 自分（OS）のキャッシュにある？
  ▼
リゾルバ（プロバイダや社内の DNS サーバー）
  │ ② リゾルバのキャッシュにある？ 無ければ聞きに行く
  ▼
ルート → .com の担当 → example.com の担当（権威 DNS）
  │ ③ 「example.com は 203.0.113.10」と答える
  ▼
答えを TTL の間キャッシュし、ブラウザへ返す
```

| 言葉 | 意味 |
|---|---|
| 権威 DNS | その名前の正しい答えを持っているサーバー |
| リゾルバ | 利用者の代わりに聞いて回り、答えを覚えておくサーバー |
| TTL | 答えをキャッシュしてよい秒数 |

問い合わせは、軽さを優先して UDP の 53 番で行います（答えが大きいときは TCP）。

### TTL（キャッシュしてよい時間）

リゾルバや OS は、TTL の間は答えを覚えておき、再び聞きに行きません。

- TTL が長い：問い合わせが減って速いが、IP を変えても **古い答えがしばらく使われる**
- TTL が短い：切り替えがすぐ伝わるが、問い合わせが増える

### 主なレコードの種類

| 種類 | 意味 | 例 |
|---|---|---|
| A | 名前 → IPv4 アドレス | `example.com → 203.0.113.10` |
| AAAA | 名前 → IPv6 アドレス | |
| CNAME | 名前 → 別の名前 | `www.example.com → example.com` |
| MX | メールの宛先サーバー | |

## 設計で決めること

### 1. TTL をいくつにするか
- 選択肢：長め（数時間〜1日）／短め（数十秒〜数分）
- 判断の基準：普段はある程度長くてよい。サーバーの引っ越しや切り替えの予定があるなら、**前もって短くしておき**、古い TTL が切れるのを待ってから切り替える

### 2. 接続先を名前で指すか、IP で指すか
- 選択肢：名前で指す／IP アドレスを直接書く
- 判断の基準：名前で指す。ロードバランサーやマネージドな DB は、IP アドレスが運用の都合で変わる。設定ファイルに IP を書くと、変わったときに繋がらなくなる

### 3. 権威 DNS をどこで運用するか
- 選択肢：自分で DNS サーバーを運用する／DNS のサービスを使う
- 判断の基準：権威 DNS が止まると、アプリが正常でも全員が繋がらなくなる。止まりにくい作りを自分で用意できないなら、DNS のサービスを使う

## 障害

| 症状 | 原因 | 確かめ方 |
|---|---|---|
| アプリは正常なのに、全員が繋がらない | 権威 DNS の障害、ドメインの期限切れ、レコードの設定ミス | `dig example.com` で、いまどの IP が返るかを見る。アプリのメトリクスが正常なら真っ先に疑う |
| 切り替えたのに、一部の人だけ旧サーバーへ行く | TTL が長く、古い答えがキャッシュに残っている | `dig` で残りの TTL を見る。切り替え前の TTL を確かめる |
| 断続的に繋がらない | IP アドレスを長時間覚え続けるプログラムが、接続先の IP の変更についていけていない | 設定ファイルに IP が書かれていないか、実行環境が名前解決の結果をどれだけ覚えるかを確かめる |

## 実行モデルで変わること
→ [[実行モデル]]

| | 作り直す型（PHP-FPM） | 常駐型（Go など） |
|---|---|---|
| 名前解決の結果 | リクエストごとに引き直すことが多い | 長く動くプロセスがどう覚えるかは、実行環境次第（Go 自身は覚えない。Java は JVM の設定で覚える時間が決まる） |
| つなぎっぱなしの接続 | リクエストが終われば捨てる | プールした接続は古い IP につながったまま残る。接続の寿命を決めておく → [[接続プール]] |
