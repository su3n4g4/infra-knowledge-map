# CDN

画像・CSS・JS などのファイルのコピーを、世界各地にあるサーバー（エッジ）に保存し、利用者に近いエッジから返す仕組み。

## なぜ必要か

サーバーが東京にあると、海外の利用者は毎回遠くまで取りに来ることになり、遅くなります。また、画像や CSS のように **誰が見ても同じもの** を毎回アプリのサーバーが返すのは無駄で、負荷も増えます。

CDN は、利用者の近くにあるエッジにコピーを置きます。2回目からはエッジが答えるので、速く、アプリのサーバーにも届きません。

## 仕組み

```txt
利用者 ──▶ 近くのエッジ
             │ キャッシュにある？
             ├ ある  → その場で返す（ヒット）
             └ ない  → 元のサーバー（オリジン）に取りに行き、
                       コピーを残してから返す（ミス）
```

| 言葉 | 意味 |
|---|---|
| エッジ | 利用者の近くに置かれた CDN のサーバー |
| オリジン | 本物を持っている場所。ファイルの保存先やロードバランサー |
| キャッシュキー | 「同じもの」と見なす条件。URL が基本で、クエリやヘッダを含めるかを選べる |

何秒キャッシュするかは、オリジンが返す `Cache-Control` ヘッダや、CDN の設定で決まります。

### 静的と動的を分ける

```txt
CDN
  ├ /assets/*  → ファイルの保存先（JS・CSS・画像）  … 長くキャッシュ
  └ それ以外   → ロードバランサー（アプリ）         … キャッシュしない
```

## 設計で決めること

### 1. 何をキャッシュするか
- 選択肢：静的なファイルだけ／動的なページも含める
- 判断の基準：誰が見ても同じものだけ。ログイン後の画面のように **人によって中身が変わるもの** をキャッシュすると、他人の画面が表示される事故になる

### 2. 更新したファイルをどう配るか
- 選択肢：ファイル名にハッシュを付ける（`app.3f9a2c.js`）／同じ名前のまま、キャッシュを消す（invalidation）
- 判断の基準：ファイル名にハッシュを付ける。中身が変わるたびに名前が変わるので、長くキャッシュしても古いものが返らない。Vite や Laravel Mix はこれを自動でやる。名前を変えられないファイルだけ、デプロイ後にキャッシュを消す

### 3. どれだけキャッシュするか
- 選択肢：オリジンの `Cache-Control` に従う／CDN の設定で決める
- 判断の基準：ハッシュ付きのファイルは長く（1年など）。名前の変わらないファイルは短く。オリジンのヘッダで決めておくと、ブラウザのキャッシュとも揃えられる

## 障害

| 症状 | 原因 | 確かめ方 |
|---|---|---|
| デプロイしたのに画面が変わらない | エッジやブラウザに古い JS が残っている | レスポンスヘッダでヒットかミスかを見る（CloudFront なら `X-Cache`）。アプリのバグを探す前に確かめる |
| 他人の情報が表示された | 人によって変わるページをキャッシュした | キャッシュの対象のパスと、Cookie や認証ヘッダの扱いを見る |
| CDN の障害のとき、アプリのサーバーまで落ちた | キャッシュが効かず、全部のアクセスがオリジンに流れ込んだ | オリジンへのリクエスト数の推移を見る。オリジン側にも余裕を持たせる |
