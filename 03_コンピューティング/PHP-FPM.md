# PHP-FPM

PHP を実行する worker プロセスを複数起動しておき、Nginx から FastCGI（9000 番ポート）で届いたリクエストを、空いている worker に1件ずつ処理させるプロセス。作り直す型のアプリケーションサーバーの代表 → [[実行モデル]]

## なぜ必要か

PHP は、リクエストが来るたびにスクリプトを最初から実行する言語です。毎回 PHP のプロセスを起動していては遅すぎるので、**あらかじめ PHP のプロセス（worker）を起動して待たせておく** 仕組みが要ります。それが PHP-FPM（FastCGI Process Manager）です。

## 仕組み

```txt
Nginx ──FastCGI :9000──▶ PHP-FPM（親プロセス）
                           ├ worker 1  処理中
                           ├ worker 2  処理中
                           ├ worker 3  空き  ← 次のリクエストはここ
                           └ worker 4  空き
```

- 親プロセスは worker を管理するだけで、PHP のコードは実行しない
- **worker 1つが同時に処理できるのは1リクエストだけ**
- worker が全部ふさがっていると、次のリクエストは空くまで待たされる

### リクエストごとに全部捨てる

1リクエストの処理が終わると、そのリクエストで作った変数や DB の接続を全部捨てます（シェアードナッシング）。

- 良い点：あるリクエストで起きた問題が、次のリクエストに持ち越されにくい
- 気をつける点：DB の接続も毎回張り直すことになる → [[接続プール]]

### worker の増やし方（pm）

| 設定 | 動き |
|---|---|
| `pm = static` | 常に `pm.max_children` 個の worker を起動しておく |
| `pm = dynamic` | 最小〜最大の範囲で、空きに応じて増減する |
| `pm = ondemand` | リクエストが来てから起動する。待機中の資源は少ないが、最初が遅い |

## 設計で決めること

### 1. worker の最大数（`pm.max_children`）をいくつにするか
- 選択肢：使えるメモリと、worker 1つが使うメモリから決める
- 判断の基準：これが **同時に処理できるリクエスト数の上限** になる。目安は「使えるメモリ ÷ worker 1つのメモリ」（例：2GB で 1つ 80MB なら 25 前後）。大きくしすぎると、メモリが足りなくなってプロセスごと強制終了される

### 2. DB の接続数の上限に収まるか
- 選択肢：worker 数と台数の組み合わせ
- 判断の基準：worker 1つが DB の接続を1本使うので、**DB の接続数 ≒ worker 数 × 台数** になる。台数を増やす前に、DB の上限に収まるか計算する → [[データベースサーバー]]

### 3. 1リクエストの処理時間の上限（`request_terminate_timeout`）
- 選択肢：設定する／しない
- 判断の基準：設定する。止まったままの処理が worker を握り続けるのを防げる。手前の Nginx のタイムアウトとの関係も見る

### 4. worker の増やし方（`pm`）
- 選択肢：static／dynamic／ondemand
- 判断の基準：専用のサーバーやコンテナで動かすなら static が分かりやすい（メモリの使用量が読める）。ほかのプロセスと同居していて、待機中のメモリを減らしたいなら dynamic

## 障害

| 症状 | 原因 | 確かめ方 |
|---|---|---|
| 急に全体が遅くなる、504 | worker が全部ふさがっている | PHP-FPM のログに `server reached pm.max_children` が出ていないか見る |
| 502 | PHP-FPM のプロセスが落ちた、メモリ不足で強制終了された | PHP-FPM のログと、サーバーやコンテナのメモリの推移を見る |
| 特定の画面だけ遅く、つられて他も遅くなる | その処理が worker を長く握っている | 遅いリクエストを探し、[[N+1問題]] や外部 API の待ちがないか見る。重い処理はキューに回すことを検討する |

`max_children` を上げれば解決するとは限りません。メモリと DB の接続数の両方の上限に当たります。

## 実行モデルで変わること
→ [[実行モデル]]

| | 作り直す型（PHP-FPM） | 常駐型（Go など） |
|---|---|---|
| 同時処理の単位 | worker プロセス | goroutine など |
| 同時処理の上限 | `pm.max_children` で自然にかかる | 自分で決める |
| 1件の致命的なエラー | その worker だけ | プロセス全体に及ぶことがある → [[panicとrecover]] |
