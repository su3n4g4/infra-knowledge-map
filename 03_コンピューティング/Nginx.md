# Nginx

80 番や 443 番ポートで HTTP を受けるプロセス。静的ファイルは自分でディスクから読んで返し、それ以外のリクエストは後ろのプロセス（PHP-FPM の 9000 番など）へ転送する。

## なぜ必要か

### 作り直す型（PHP など）では必須
PHP-FPM は HTTP を直接受け取れません。FastCGI という別の形式でしか話せないので、**HTTP を受けて FastCGI に変換して渡す役** が要ります。それが Nginx です。

### 常駐型（Go など）では必須ではない
Go などはプロセス自体が HTTP を受けられるので、Nginx がなくても動きます。置くのは、次のような **はっきりした理由があるとき** です。

- 静的ファイルの配信を任せたい
- 流量の制限や URL の書き換えを、アプリの外でやりたい
- 通信の遅いクライアントへの対策を1つはさみたい（後述のバッファリング）

## 仕組み

### リバースプロキシ

利用者の代わりに、後ろのサーバーへ取り次ぐことを **リバースプロキシ** と呼びます。

```txt
ロードバランサー ──HTTP :80──▶ Nginx ──┬─ 静的ファイル（/assets/*）→ 自分で返す
                                      └─ それ以外 ─FastCGI :9000─▶ PHP-FPM
```

設定はおおむね次の形です。

```nginx
server {
    listen 80;
    root /var/www/public;

    location / {
        try_files $uri /index.php?$query_string;   # ファイルが無ければ PHP へ
    }

    location ~ \.php$ {
        fastcgi_pass 127.0.0.1:9000;               # PHP-FPM へ渡す
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }
}
```

### バッファリング

通信の遅い利用者がいると、レスポンスを少しずつしか送れません。Nginx はレスポンスをいったん自分で受け取って溜め、後ろのプロセスをすぐ解放します。後ろの PHP-FPM の worker が、遅い利用者に付き合って待たされずに済みます。

### 少ないプロセスで多くの接続を扱う

Nginx は少数のプロセスで、多数の接続を同時に扱えるように作られています。接続を受けることは Nginx が引き受け、重い処理は後ろに任せる、という分担です。

## 設計で決めること

### 1. Nginx を置くか
- 選択肢：置く／置かずにロードバランサーからアプリへ直結する
- 判断の基準：作り直す型なら必ず置く。常駐型なら、静的配信・流量の制限・遅いクライアントへの対策のどれかが要るときだけ置く。理由なく置くと、運用するものが1つ増えるだけになる

### 2. タイムアウトをどういう関係にするか
- 選択肢：`keepalive_timeout`（初期値 75 秒）、`fastcgi_read_timeout`（初期値 60 秒）と、手前のロードバランサーのタイムアウトの関係
- 判断の基準：`keepalive_timeout` はロードバランサーのタイムアウトより長くする（短いと 502 の原因になる）。処理を待つ時間は、外側ほど長くすると、どこで切れたかが分かりやすい

### 3. 受け取れるリクエストの大きさ
- 選択肢：`client_max_body_size`（初期値 1MB）を変えるか
- 判断の基準：ファイルのアップロードがあるなら、想定する最大の大きさに合わせて上げる。超えると 413 が返る

### 4. 後ろのプロセスとどうつなぐか
- 選択肢：TCP のポート（`127.0.0.1:9000`）／UNIX ソケット
- 判断の基準：コンテナで Nginx と PHP-FPM を別のコンテナにするなら、同じタスクの中で `localhost:9000` でつなぐ形がよく使われる。同じサーバーの中だけなら UNIX ソケットでもよい

## 障害

| 症状 | 原因 | 確かめ方 |
|---|---|---|
| 502 | PHP-FPM が落ちている、または 9000 番に繋がらない | Nginx のエラーログに、どこに繋げなかったかが出る。502 はロードバランサーも返すので、どちらが返したかを先に確かめる |
| 504 | PHP-FPM の処理が `fastcgi_read_timeout` を超えた | 遅かったリクエストと、その処理時間をアプリのログで見る |
| 画像のアップロードだけ失敗する（413） | `client_max_body_size` を超えた | アプリではなく Nginx のエラーログを見る |

## 実行モデルで変わること
→ [[実行モデル]]

| | 作り直す型（PHP-FPM） | 常駐型（Go など） |
|---|---|---|
| Nginx の位置づけ | 必須（PHP-FPM は HTTP を受けられない） | 理由があれば置く |
| 置かない場合 | 動かない | タイムアウトや流量の制御を、アプリのコードで持つ → [[Goのnet_http]] |
