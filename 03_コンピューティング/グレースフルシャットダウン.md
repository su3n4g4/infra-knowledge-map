# グレースフルシャットダウン

プロセスが終了のシグナル（SIGTERM など）を受けたとき、新しいリクエストの受付を止め、処理中のリクエストを終えてから終了する止め方。

## なぜ必要か

デプロイのたびに、古い版のプロセスは止められます。このとき、処理の途中でいきなりプロセスを止めると、そのリクエストは失敗します。利用者には 502 が見え、DB の更新が途中で終わることもあります。

**「受付を締める → 処理中を片付ける → 終了する」** という順番を守れば、デプロイ中でもエラーを出さずに入れ替えられます。

## 仕組み

### シグナル

OS がプロセスに送る合図を **シグナル** と呼びます。

| シグナル | 意味 | 受け取ったプロセスは |
|---|---|---|
| SIGTERM | 終了の要求 | 後片付けをしてから終了できる（何もしなければ、すぐ終了する） |
| SIGQUIT | 終了の要求（プログラムによって意味が違う） | PHP-FPM や Nginx は、処理中を待ってから終了する |
| SIGKILL | 強制終了 | 何もできずに終わる |

### 止めるまでの流れ

ロードバランサーの後ろで動いているプロセスを止めるときは、次の順番になります。

```txt
① ロードバランサーの転送先から外す
   新しいリクエストは送られなくなる（処理中のものは続く）
   ↓ 外すときの待ち時間の間、処理中が終わるのを待つ
② プロセスに終了のシグナルを送る
   ↓ アプリは処理中を終えて、自分で終了する
③ 猶予時間が過ぎても終わらなければ SIGKILL
```

②で、アプリが **シグナルを受け取って正しく後片付けするか** がアプリ側の責任です。

- [[デプロイの流れ]]（⑦）：[[ローリング更新]] → [[ロードバランサー]] から外される → **終了のシグナルを受けて終了**
- [[コンテナの仕組み]]（Docker / OCI）：docker stop が PID 1 に SIGTERM を送り、10秒で止まらなければ SIGKILL を送る

## 設計で決めること

### 1. どのシグナルで止めるか
- 選択肢：SIGTERM／SIGQUIT
- 判断の基準：止めるプログラムが「処理中を待って終わる」シグナルを使う。PHP-FPM は SIGQUIT で処理中を待ち、SIGTERM ではすぐ止まる。コンテナでは、イメージの `STOPSIGNAL` で送るシグナルが決まる（公式の php-fpm のイメージは SIGQUIT を設定している）。Go は自分で受けるので SIGTERM でよい

### 2. 猶予時間をいくつにするか
- 選択肢：シグナルから強制終了までの時間
- 判断の基準：**一番長いリクエストの処理時間 < アプリの後片付けの時間 < 強制終了までの猶予時間** の関係にする

### 3. 処理中の長い仕事をどう扱うか
- 選択肢：最後まで待つ／区切りのよいところで止めて、残りをやり直せるようにする
- 判断の基準：猶予時間に収まらない仕事（バッチやキューの処理）は、区切りのよいところで止まり、途中から再開できるように作る

## 障害

| 症状 | 原因 | 確かめ方 |
|---|---|---|
| デプロイのたびに 502 が少し出る | 終了のシグナルで、処理中のリクエストを切っている | 普段は出ず、デプロイのときだけ出るなら、まずこれを疑う。アプリがシグナルを受けて待つ作りになっているか確かめる |
| デプロイ中に DB の更新が中途半端に残る | 処理の途中で強制終了された | 強制終了までの猶予時間と、処理にかかる時間を比べる |
| デプロイが遅い | 外すときの待ち時間が長すぎる | 一番長いリクエストの処理時間に比べて、待ち時間が長すぎないか見る |

## 実行モデルで変わること
→ [[実行モデル]]

| | 作り直す型（PHP-FPM） | 常駐型（Go など） |
|---|---|---|
| 何もしないと | SIGTERM ではすぐ止まる | SIGTERM ではすぐ止まる |
| 正しく止めるには | SIGQUIT で止める（`STOPSIGNAL` を確認） | 止める処理をコードで書く |

Go では次のように書きます。`Shutdown` は、新しい受付を止め、処理中のリクエストが終わるのを待ちます。

```go
ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGTERM, os.Interrupt)
defer stop()

go func() {
    if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
        log.Fatal(err)
    }
}()

<-ctx.Done() // シグナルを待つ

shutdownCtx, cancel := context.WithTimeout(context.Background(), 25*time.Second)
defer cancel()
srv.Shutdown(shutdownCtx)
```

## 実装の例

| 環境 | シグナルを送るもの | 猶予時間の設定 |
|---|---|---|
| オンプレ | systemd（`systemctl stop`） | `TimeoutStopSec`、送るシグナルは `KillSignal` |
| AWS | [[ECS]] | タスク定義の `stopTimeout`（初期値 30 秒） |
